# 磨耳朵专辑与连续听力

## 用户诉求

在日常练习之外新增独立磨耳朵模块，连续播放已有课程音频，后续可添加不同分类/专辑的外贸音频；用户同意同时设计与实现。

## 实现

- 小程序四个原生 Tab：课程、磨耳朵、复习、我的；新增专辑目录、曲目详情、可选文本及播放器。
- 全局后台队列负责连续播放、断点、循环和定时关闭。其他 Tab 共享迷你播放器；本机听力统计独立于精练和完成记录，签名 URL 不持久化。
- 音频焦点协调课程/听力/复习；清理旧后台订阅、延迟 seek、自动播放和速度恢复竞态，避免新旧音源互相抢占。
- Web 新增听力专辑管理，支持草稿、顺序、上下架、权限、原文及带进度/取消的上传；版本冲突保留草稿。
- 后端增加专辑与队列 API、管理员目录维护及最大 60 MB 私有流式音频上传，签名媒体支持 Range/HEAD。内置章节源与第一章试学规则不可绕过；沿用已有免费和会员开关。

## 受影响模块

- 小程序：`pages/listening`、`components/listening-mini-player`、`utils/listening-player*`、`audio-focus`、`background-audio-events`、应用生命周期和课程/复习衔接。
- Web：`ListeningAdmin.tsx`、管理台入口、上传客户端和说明。
- 后端：`waimaoListeningService.ts`、`waimao-listening.ts`、路由挂载及回归测试。
- 文档：`LISTENING.md`、架构/前端/安全/稳定性/质量说明及执行计划。

## 同日回归修复：小程序无法启动

用户反馈新增功能后小程序被改坏。直接读取微信开发者工具，确认新增听力页的 16 处表达式把 `&&`、`<` 写成 HTML 实体，导致 WXML 编译失败并阻止整个小程序启动。此前的 JS 模拟测试没有编译模板，未发现该问题。

仅修正 `pages/listening/listening.wxml` 的表达式运算符，同时将标题中被原样显示的实体改为实际 `&` 符号；在 `tests/listening-page.test.ts` 增加全仓库模板表达式检查，并同步生成 JS。新测试在修复前明确失败、修复后通过。使用微信工具随附的离线编译器验证全部 15 个 WXML 通过，完整小程序测试及 87 份生成 JS 一致性检查通过。开发者工具实测首页、原课程详情、复习和“我的”可正常打开，原编译错误消失。

另确认线上听力目录接口仍为 404，原课程目录为 200：新后端尚未部署，不能将本地启动恢复等同于听力功能可上线。同步更新 `LISTENING.md` 的验证和发布清单。本轮不修改登录、会员配置、原课程播放逻辑或线上服务，不提交或推送。
